# 实现架构

## 每日流水线

`抓取职位 → 标准化 → 去重 → 硬条件过滤 → 语义评分 → Top 10 → 生成材料 → 人工确认 → 填表`

### 1. 抓取与标准化

首批适配 Greenhouse、Lever 和 Ashby 的公开职位接口。每条职位统一为 `company`、`title`、`location`、`salary`、`description`、`sourceUrl`、`externalId`、`publishedAt` 和 `source`。

### 2. 去重与硬条件

使用来源 ID 和“公司 + 标准化职位名 + 地点”的指纹去重。地点、签证、最低薪资、职级和黑名单属于硬条件，不满足的职位不进入模型评分。

### 3. 匹配评分

建议总分 100：技能/职责 35，经历证据 25，职级 15，地点与工作方式 10，薪资 10，个人偏好 5。评分结果必须附带引用自简历或职位描述的理由，不能只给关键词相似度。

### 4. Top 10 与材料

每天只处理新出现且达到阈值的前 10 个职位。材料生成只能重排和改写已存在的经历，不得虚构技能、数字或雇佣事实。

### 5. 自动填表边界

浏览器层使用按 ATS 划分的适配器。姓名、联系方式、简历上传等确定字段可以自动填写；自愿披露、薪资预期、签证、犯罪记录、开放题和验证码必须按个人规则或转交用户。最终提交默认需要人工确认，并保留页面截图、填写内容和时间戳。

## 下一阶段模块

- `sources/`：职位源适配器
- `scoring/`：硬条件、匹配评分和解释
- `profile/`：简历事实库与偏好
- `applications/`：申请状态、材料版本和审计记录
- `automation/`：每日调度与浏览器填表
- `app/`：本地操作界面
